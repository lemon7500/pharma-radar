# 精选与校准

Pharma Radar 将文献收录、研究导读就绪和精选分别判断。评分高不代表论文结论已经验证，已处理也不代表导读完整。人工评判见 [标注规范](annotation-protocol.md)、[代表性判断卡](annotation-cards-2026-10-06.md) 和 [空白标注表](annotation-worksheet.csv)；期刊来源见 [指标说明](journal-metrics.md) 与 [登记表](../industry/journal-metrics.json)。

## 一条资料怎么变成精选

1. **采集与文献身份**：按来源网址、内容身份去重，论文使用文章自身 DOI，保留来源和旧文章入口。科研文献信息、可获取摘要和原文地址单独保存；参考文献 DOI 不作文章身份。材料过短或无法获取时保留索引，不凭标题补研究结论。
2. **先可见的索引**：已启用的信源中，身份、发表日期、原文入口与药学关联明确的文献可先出现在资料库，标为“导读整理中”。这一阶段没有研究结论、实验阶段或精选资格。
3. **预筛**（`prefilter.md`）：判断药学收录边界。`BLOCK` 停止本轮自动分析并退出正常资料池；`PASS` 和 `UNKNOWN` 继续处理。材料缺失造成的阻断按未知处理，不能推断论文没有价值。是否保留旧详情入口由公开可见性和兼容规则另行决定，`BLOCK` 不等于删除所有历史链接。
4. **评分**（`selection-score.md`）：保持七类内容、五轴整数加权；同一标准作两次评分，每次 0–100。两次之和 ≥ 2 × 信源门槛，形成评分上的入选判断。后台及兼容 API 的历史分数是两次平均向下取整；读者界面侧重来源、时间、阶段和完整度，不显示 AI 分数。
5. **写作与结构化**：评分和结构化可并行。达到入选门槛或两次平均严格高于 `understandFloor` 的条目使用内容理解写法，其余使用简短标题摘要写法。研究对象、方法、结果、局限及阶段仍需来自实际材料并通过来源片段校验；评分较高不放宽这一条件。
6. **统一公开判断**：通过 `publication/` 发布。资料必须符合来源参与方式、可见性和收录资格；学术精选还须研究信息 `ready`。预印本不自动精选，只有经审计的人工精选覆盖才可进入。人工修正与模型评分分别保留，药学关联通过不自动产生精选资格。
7. **事件归组与发布**（`group-*.md`）：不同来源报道同一件事归组，热点以事件组织。新精选等待归组，或等最多 3 分钟的发布门；已公开索引在等待精选发布时仍可正常阅读。这里的短等待不是采集与模型队列的最长耗时保证。
8. **日报、周报、月报**（`report-*.md`）：北京时间每天 08:00 出日报，每周一 10:00 出周报，每月 1 日 10:30 出月报。精选公开时间决定刊期候选归属，跨过刊期边界才确定精选公开时间的进入下一期候选池；截止前已确定公开时间但仍在提交的事务会等提交后读取。刊载受事实去重和版面容量限制，并非全部精选必进简报。

读者时间线按来源发表日期组织；本站收录时间用于观察运维耗时，晚收录不会增加研究时效性。来源仅有日期时不虚构时刻。预算等待、处理重试和材料不足另有状态，模型调用次数不等于文章数。

各步骤的提示词在 `industry/prompts/`。提示词版本按内容哈希记录，之后的调用使用新版本；旧结果不会仅因文件改变而自动全部重算，旧稿修复与重跑另走版本、材料指纹和预算流程。

## 现有门槛与人工草案

`industry/selection.ts` 的代码默认值为：

```ts
export const SELECTION = {
  thresholds: { T1: 60, T1_5: 65, T2: 76 },
  understandFloor: 50,
};
```

信源的实际分级由配置或后台决定。当前五个配置的采集信源均为 `T1_5`，对应 65 分；该分级不代表其中每篇都是原始一手研究，出版商简讯仍是二次报道。`EXCLUDE_MP` 或没有门槛的分级不参与自动精选。实际公开精选还要通过上一节的来源、研究就绪和预印本条件。

这些数值沿用已有实现，尚未完成 Pharma Radar 的独立人类样本校准。人工规范中的“内容 90 分 + 期刊参考 10 分”是教学草案，没有替换线上五维结构、模型输入或门槛；[期刊指标登记表](../industry/journal-metrics.json) 当前也不参与自动计算。

## 校准

### 1. 准备标注材料

先用 12–15 篇讨论规则，再以约 40 篇开发集和另 20 篇留出集作阶段检查；必要时扩到 100–200 篇。同一论文或同一研究事件的不同报道、版本放在同一组，避免跨集合泄露。抽样覆盖专题、原始研究、综述、方法、简讯、预印本、临床与监管，以及材料不足和范围外难例。

只有未受建议引导的人类判断才计入独立人类标签。用户委托助手编辑、同意继续推进、看到建议后同意结论，都不能冒充独立金标准。已经用于教学或调规则的材料不能再作为留出检验。当前代表性判断卡有助手建议，只供教学与开发。

分别记录原始人工决定、理由、读者对象、未知事项、材料版本、标注者、日期和是否先看到建议。未知不填 0；关键项目未知时不报完整总分。期刊年度、JCR 版本或相关类别位置无法核对时留空，高指标不能覆盖内容问题。

### 2. 转为评测格式

审核标签后，将评测输入存入私有 `.data/gold.jsonl`，不提交密钥或完整来源材料。每行一条；下面只是格式示例，假设来源明确提供了发表时刻：

```json
{"caseId":"pharma-dev-001","material":{"title":"原始论文标题","originalTitle":null,"publishedAt":"2026-10-01T09:00:00+08:00","publishedAtSource":"2026-10-01T09:00:00+08:00","sourceName":"信源名称","bodyZh":null,"bodyOriginal":"已获取的摘要……"},"sourceFacts":{"sourceKind":"json_list","sourceTier":"T1_5","firstParty":false,"language":"en"},"samplingContext":{"benchmarkSplit":"development","samplingStratum":"original-computational"},"gold":{"decision":"select"}}
```

`publishedAt` 保存被接受的来源发表日期 / 时间，未知留空；可选 `publishedAtSource` 保存实际来源日期字节，`publishedAtUnit` 可注明 `epoch_s`、`epoch_ms` 或 `yyyymmdd`。不要把数据库导出的规范化 ISO 串误当原始来源字节。仅日期不附时刻，来源明确提供真实时刻时才保留；旧格式中的 UTC / UTC+8 午夜保守按日期处理，不重新生成虚构 08:00。

可选 `material.bibliography` 保存已核对文献元数据，沿用现有研究字段格式；已修正的书目发表日期应随样本导出，才能在评测中复现生产的日期优先级。旧文件没有该字段时仍可运行，但不能宣称已验证书目日期纠正。

评测与生产评分、结构化及写作共用日期表达。未知发表时间不使用收录时间补位，非法 ISO / `yyyymmdd` 日不会被自动滚动到下月。有效书目日期与来源时刻明显冲突时，以书目日期为主；同一天保留准确时刻。UTC 与北京时间跨日能够解释差异时，注明书目日期并保留真实带区时刻，不把两个来源的日期和时刻拼成一个值。编辑审计中的文献日期修正同样用于后续模型输入。

| 字段 | 说明 |
|---|---|
| `caseId` | 唯一编号，对应人工台账 |
| `material` | 原题、被接受的来源发表日期、可选原始日期字节及单位、信源名和实际已获取正文 / 摘要；`bodyZh` 或 `bodyOriginal` 至少一个可用 |
| `sourceFacts` | 来源类型、分级、一手属性、语言；分级决定使用哪个门槛 |
| `samplingContext` | `benchmarkSplit` 分开发与留出集；`samplingStratum` 区分材料类别 |
| `gold.decision` | `select` 推荐，`reject` 不推荐，`either` 暂无决定；`either` 不计入决定性指标 |

研究精选和学习精选都可映射为 `select`；普通收录与明确边界不符可映射为 `reject`，但在人工台账保留不同原因。待核对先补材料，或暂列 `either`；不要直接当成研究没有价值。监管 / 产业的“资讯精选”在其独立分层中映射为 `select`，评价事件关注价值，不混入论文研究质量盲测。助手建议不自动写入 `gold`。

`industry/gold.example.jsonl` 是框架的虚构 AI 行业格式示例，不是药学样本或本站金标准。评测格式尚不包含期刊指标和细化人工评分，不得称其已经验证 JIF 权重。

### 3. 跑开发集评测

```bash
node --env-file=.env scripts/eval-selection.ts --gold .data/gold.jsonl --split development --label "第一版药学评分校准"
```

对每条样本执行预筛和两次评分，输出查准率、查全率、准确率、F1、错误案例，以及 40–90 每隔 2 分的门槛扫描。报告写入私有 `.data/eval/`，默认导入后台 SelectBench。

默认评测跟随当前“精选评分”模型路由；`--models` 可显式比较模型，`--n 200` 限制样本数。先确认材料与标签，评测会调用模型并消耗预算；读者打开网页不会触发这些调用。不要为尚无独立标签的空表启动付费校准。

同次运行中完全相同的评分输入可共享模型结果，各条仍按自身预筛、分级门槛及 `gold` 计分。后续相同输入与版本可复用回执，但新输入、版本变化或失败重试可能继续消耗预算。报告的 token 与平均耗时汇总相关回执的所有服务商尝试；缓存重跑显示累计历史用量，不表示本次新增费用。

### 4. 修标准，再检验留出集

逐条区分错误来源：边界误收、材料不足或事实错误先修复；价值定义不清再改评分规则；只有整体偏松或偏紧且开发样本支持时才讨论门槛。保留七类内容、五轴加权、噪声压制和输入安全边界，不为了精选比例凑标签或移动门槛。

开发调整完成后，在未曝光的新留出集上运行一次检查，单独报告样本数、错误数和各分层表现。20 篇只能作为阶段检验；不能凭一个高准确率宣称全面可靠。看过留出错误并据此修改规则后，该集合转为开发材料，下一次需要新的留出样本。

此工具评测的是筛选判断，不是完整公开发布流程，也不验证统计值、实验阶段、材料完整性、期刊来源或人体疗效。内容可靠性与兼容检查仍按 [可靠性修复](research-reliability.md) 和 [v2 发布流程](pharma-radar-v2.md) 单独完成。

## 换模型

后台“模型与评测”显示当前路由、成功率、耗时和 token 用量。更换评分模型前用相同的已审核开发样本比较，之后用未曝光留出样本验证；模型名称或高期刊指标不能代替验证。新路由只影响后续任务，旧结果重跑仍受回执和预算规则限制。
