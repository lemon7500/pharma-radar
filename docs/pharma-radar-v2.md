# Pharma Radar v2

面向药学学生与研究者。英文品牌，中文研究阅读；Render、Supabase、GitHub Actions、DeepSeek 和原域名沿用。

## 阅读与分类

主导航为导读、资料库、专题、研究简报、阅读清单。导读页的编辑精选必须已完成研究结构整理；不足时明确展示最新收录。资料库使用紧凑条目，研究环节、重点专题、内容形式、证据阶段与来源属性独立组合：同维度多选使用 OR，不同维度使用 AND。检索、排序、分页和分享链接保留条件。

中药与天然产物、AI 药物研发可同时归属。研究阶段支持计算、体外、动物、临床；只有明确来源支持才显示临床分期。来源属性不表示证据质量。AI 评分只用于后台编辑判断，兼容 API 中的历史字段保留。

## 研究材料与依据

原生 Europe PMC 字段提供作者、期刊、DOI、发表日期、文献类型和摘要。已有 Nature/Europe PMC 条目在采集或旧稿整理中查询免费文献记录，只接受 DOI/PMID 与原文标题同时匹配的记录。文章自身 DOI 用于去重，参考文献 DOI 不作为文章身份。

研究问题、对象、方法、结果、局限与阶段必须附已获取材料中的逐字片段；系统验证词表、片段、数值和临床分期。仅标题、过短材料、参考文献列表暂停深入导读，保留索引与原文链接。模型摘要仍需人工核对其语义；有疑问可从详情页反馈，并在后台查看依据、修正或重试。

`articles` 保存文献元数据、研究结构与私有依据，`publications.research` 是统一公开投影。新来源摘要单独保存，不覆盖历史正文及翻译。人工修正附原因与版本，经审计和原有统一发布流程生效。来源依据和原始材料仅后台显示。

## 渐进整理与暂停

新稿沿用现有结构化步骤提取研究信息。旧稿在正常任务后处理，滚动 24 小时最多 20 篇；并发任务共享数据库锁和上限。继续受现有分钟、小时和日请求预算限制，预算不是金额上限。

GitHub 仓库变量 `RESEARCH_BACKFILL_ENABLED=true` 开启旧稿整理。后台“运行”可暂停／恢复回填，查看待处理、材料不足、失败重试、24 小时处理量、数据库大小和回填模型请求。暂停后正常采集与阅读继续工作。失败条目等待 24 小时重试，后台可安排重试但不能绕过每日上限。

## 兼容与迁移

迁移 `0041`、`0042` 只增加列和索引。启动时为旧投影补默认研究信息，不调用模型。旧分类键、文章和专题链接、RSS、REST v1、MCP 保留；MCP 前缀仍为 `pharma_radar`。浏览器收藏、已读与主题存储键保持不变，原有导入导出继续可用。

字体为本地 WOFF2 Unicode 子集：Noto Serif SC、Noto Sans SC、IBM Plex Sans，使用 `font-display: swap` 和系统字体后备；OFL 许可证在 `apps/web/public/fonts`。

## 发布与恢复

1. 本地样本、类型检查、后端与网页回归、浏览器桌面／手机／平板及深浅色验证。
2. 手动触发 `pharma-backup.yml`，确认 backup 和 verify 均成功；verify 在一次性 PostgreSQL 17 中真正恢复加密备份。
3. 应用增量迁移，部署新版。先少量旧稿验证元数据与依据，再开启渐进整理。
4. 上线后检查采集、队列、材料不足比例、数据库大小和模型账单。数据库达到 400 MB 或同一批次连续失败 3 次会自动暂停回填并记入审计，正常采集与阅读继续；可从后台检查原因并恢复。请求预算耗尽时结束当前回填批次。

需要回滚时，旧版本可读取新增列仍然存在的数据库；暂停回填后回退应用即可。不要直接删除新列。备份恢复至隔离数据库验证后，再按实际故障决定恢复范围。
