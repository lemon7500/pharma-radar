# Pharma Radar 小范围读者试用

准备日期：2026-10-08。状态：说明与空白表已准备，尚未据此招募或完成真实读者试用。本说明不改变精选规则、权重或门槛，也不表示已具备大范围推广的验收结论。

试用目标是检查药学学生和研究者能否发现资料、识别发表时间与材料范围、找到原文并保存阅读线索。**助手自测不算真实读者试用；任务反馈不算独立精选标签，也不用于计算精选准确率。** 人工推荐与正式校准另按[标注规范](annotation-protocol.md)进行。

## 参与与记录

建议首轮由运营者安排 5–8 位自愿读者，兼顾入门学生、有基础的学生与研究者，使用日常浏览器完成约 20–30 分钟任务；至少覆盖手机和电脑。人数是安排建议，不能代表总体用户或证明网站零错误。本轮只准备材料，不代发邀请或联系读者。

入口：[Pharma Radar](https://pharma-radar.onrender.com)。无需注册。免费服务可能休眠；若遇到启动等待或请求失败，记录实际等待和提示，不连续刷新。只做下表任务，不要求购买全文、付费或上传资料。

将[空白反馈表](reader-trial-feedback.csv)另存为私人副本，每位读者填写一份。只用自定代号和读者类型，不需姓名、单位、邮箱或病历。耗时可粗略记录，无法完成就记录停在哪一步，不由助手代填成功。填写后的表、阅读清单导出文件和截图不提交公开仓库；截图先遮盖账号、通知及其他无关内容。

## 任务卡

先尝试独立完成，再说明哪里不清楚。协调者可以解释入口，但应记录“提示后完成”。任务中的文献由读者从当时的公开资料选择；缺少对应样本或分页时记“未测试”，不把没有结果当作操作成功或系统故障。

| 编号 | 请读者完成 | 记录要点 |
|---|---|---|
| T01 发表时间 | 在导读选一条资料，说出原始发表日期；展开“文献信息与时间”，区分发表和本站收录时间。若有可靠时刻，再查看其时区。 | 能否找到日期，是否把晚收录当成较新研究；只有日期时是否理解为来源没有提供可靠时刻，而非午夜发表。 |
| T02 组合检索 | 在资料库选一个重点专题、一个研究环节，再加入关键词或发表日期范围；查看当前条件，并移除一个条件。 | 是否能理解不同维度共同限制、同维度多选并集；筛选无结果时能否放宽条件。尚未补齐研究字段的资料可能不匹配阶段筛选。 |
| T03 条件保留 | 在上一步结果中改变“发表最新／发表最早”排序；有多页时翻页，打开一条详情再返回；复制当前检索地址，在同一浏览器新标签打开。 | 排序、日期、关键词及筛选是否保留，返回是否容易；无分页时分别记录已做和未做部分。相关度排序只在有关键词时出现。 |
| T04 来源与材料 | 在详情找到期刊／来源、DOI（若有）和“本篇导读的材料范围”或“资料索引”，用一句话说明本站目前获取了什么。 | 能否区分摘要、摘要与补充材料、已核对正文及材料不足；“导读整理中”是否让人误以为已有完整导读。缺少字段不等于研究未做相应实验。 |
| T05 证据范围 | 选一条有研究阶段的资料，说明结果在哪一层开展；若是综述，说出“涵盖的证据”与本篇实施试验的区别。 | 是否把计算、体外或动物结果当作人体疗效；来源属性是否被误认成质量等级。没有阶段依据的资料记“待确认”，不猜测。 |
| T06 文献身份 | 找到一条预印本和一条二次报道（分别记录，缺少哪类就标未测试），说明页面提示；二次报道通过自身原文核对其文献身份。 | 能否识别尚未确认同行评议，以及简讯与被报道研究的区别；不要把简讯 DOI 当成原始研究 DOI。此任务不要求作精选判断。 |
| T07 收藏与本机保存 | 收藏两条资料，进入阅读清单后刷新；切换“最近收藏／最近发表”和“仅看未读”。如愿意，可导出到本机，再在单独浏览器配置中导入。 | 收藏是否保留、排序与已读是否易理解；能否说出换设备不会自动同步。导入导出可不做，不能为测试清空原浏览器数据；导出文件无需交给维护者。 |
| T08 原文核对 | 从详情点击“阅读原文”或 DOI 入口，核对原文标题与本站文献身份；返回本站。 | 原文入口是否容易找到，是否指向相应资料；若来源拒绝访问或要求订阅，记录外部限制，不购买、不绕过访问限制。 |
| T09 手机阅读 | 用实际手机阅读一条长标题详情；打开组合筛选并查看已选条件；通过底部入口和“更多”找回阅读清单。可按阅读习惯切换深浅色。 | 有无横向溢出、遮挡、难点按钮、看不清的日期或材料提示；未使用实际手机时不记手机试用通过。 |
| T10 错误反馈 | 从详情进入“报告元数据或导读问题”，核对所附页面地址，草拟“看到什么、期望什么、如何复现”。没有自动附上地址时手动填入站内链接。 | 能否定位反馈入口、草稿是否可理解；一般试用可只填私人表。确有问题并自愿提交站内反馈时，记录反馈编号，避免反复发送测试内容。 |

站内反馈提交后，内容、选填邮箱、页面信息及附图会保存到服务器；反馈草稿、收藏和已读记录保存在当前浏览器。提交前可查看[隐私说明](https://pharma-radar.onrender.com/privacy)。阅读清单不提供账号同步，试用反馈表也不是站内新功能。

## 如何填写与处理

每个任务结果使用“独立完成／提示后完成／未完成／未测试”；T06、T07 等含多个操作时，在实际观察里分别列出，部分完成不要记成全部完成。写下真实看到的文案、站内链接、必要的原文链接和复现步骤。无法确认的内容问题注明“待核对”，不能仅凭印象判错。

问题类型可填“内容事实／文献身份／时间／检索／材料说明／操作／布局／性能／建议”。影响程度使用“关键／主要／一般”：关键表示会误导研究结论、日期或文献身份；主要表示阻止完成阅读检索等任务；一般表示仍可完成但不顺畅。类型和程度是排查线索，不是论文评分。

运营者汇总各任务实际尝试人数、独立完成人数、提示后完成人数、失败和未测试项，分别列出手机／电脑表现；不要将未测试项计入通过率。先核实并修复关键事实问题、来源错链及阻断任务的问题，再安排相关读者复测。复测保留原记录与修复版本，不覆盖第一次观察。无现成对应资料的任务待后续补测，不制造示范研究冒充线上资料。

首轮结束后交付真实问题清单、已修复与待处理项、复测结果和仍缺的读者／设备／内容类型。是否扩大试用应依据这些记录及运维状态再决定；少量试用不能替代持续纠错、材料复核或独立精选校准。相关规则见[内容可靠性](research-reliability.md)和[编辑判断](editorial-quality.md)。
